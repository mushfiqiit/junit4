

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `AssumptionViolatedException(String, boolean, Object, Matcher<?>)` parameter `Object value` | `@Nullable` | The single-argument constructor intentionally calls this constructor with `null` for `value`. |
| `AssumptionViolatedException(String, boolean, Object, Matcher<?>)` parameter `Matcher<?> matcher` | `@Nullable` | The single-argument constructor intentionally calls this constructor with `null` for `matcher`. |
| `fValue` field | no annotation | The reported warning is about passing `null` to constructor parameters, not about the field itself, and the reduced constructor does not assign the field. |
| `fMatcher` field | no annotation | Same as above: the field is not part of the reported unsafe `null` pass. |

No return types are involved because these are constructors.

## B) Cause of the warning

The warning points to:

```java
this(assumption, false, null, null);
```

in the single-argument constructor. NullAway treats unannotated constructor parameters as `@NonNull`, but the literal `null` values are `@Nullable`. Therefore, passing `null` for the `Object value` and/or `Matcher<?> matcher` arguments is unsafe under NullAway’s defaults. Marking those parameters as `@Nullable` makes the `null` arguments type-correct and resolves the reported warning.
