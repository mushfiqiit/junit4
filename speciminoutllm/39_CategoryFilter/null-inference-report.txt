

## A) Annotation decisions

| Location | Inferred annotation | One-sentence reason |
|---|---:|---|
| `Categories.CategoryFilter.copyAndRefine` parameter `classes` | `@Nullable` | It is called with the constructor’s `includes`/`excludes` arguments, which are `@Nullable`, and the original implementation explicitly null-checks `classes` before using it. |
| `Categories.CategoryFilter.copyAndRefine` return type | `@Nonnull` left unannotated | The original method returns a freshly created `LinkedHashSet`, so its return value is never null. |
| `CategoryFilter.included` and `CategoryFilter.excluded` fields | `@Nonnull` left unannotated | These final fields are assigned the non-null result of `copyAndRefine`. |

## B) Cause of the warning

The warning is triggered at `included = copyAndRefine(includes);` because `includes` is a constructor parameter annotated `@Nullable`, but the `classes` parameter of `copyAndRefine` has no nullability annotation. Under NullAway’s default, an unannotated method parameter is `@Nonnull`, so passing the nullable `includes` argument is treated as unsafe. Annotating `copyAndRefine`’s `classes` parameter as `@Nullable` resolves the warning because the original method accepts and null-checks that argument before dereferencing it.
