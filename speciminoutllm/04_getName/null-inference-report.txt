

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `junit.framework.TestCase.fName` field | `@Nullable` | The field is not initialized and can remain unset, and original JUnit code treats test-case names as potentially null. |
| `junit.framework.TestCase.getName()` return type | `@Nullable` | The method directly returns `fName`, which is nullable, so the method must declare a nullable return type. |

## B) Cause of the warning

The warning is triggered by `return fName;` in `TestCase.getName()`. The field `fName` is annotated `@Nullable`, while `getName()` has no return-type annotation and is therefore treated by NullAway as returning `@NonNull`. Returning a `@Nullable` expression from a `@NonNull` method is unsafe under NullAway’s default non-null assumption. Annotating `getName()` as `@Nullable` aligns the method contract with the fact that the name may not have been set.
