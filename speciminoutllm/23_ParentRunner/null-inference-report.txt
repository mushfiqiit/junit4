

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `ParentRunner#createTestClass(Class<?> testClass)` parameter `testClass` | `@Nullable` | This parameter is called from the `ParentRunner` constructor with its `@Nullable` `testClass` argument, so it must be allowed to accept `null`. |
| `ParentRunner` constructor parameter `testClass` | `@Nullable` | Preserve the existing nullability evidence that callers may pass `null` to the constructor. |
| `ParentRunner#testClass` field | leave unannotated / effectively `@Nonnull` | The field is assigned from `createTestClass(...)`, whose return type is non-null by default. |

## B) Cause of the warning

The warning is reported at:

```java
this.testClass = createTestClass(testClass);
```

inside the `ParentRunner` constructor. The constructor parameter `testClass` is declared `@Nullable`, but `createTestClass` has no nullness annotation on its parameter, so NullAway treats that parameter as `@NonNull`. Passing a `@Nullable` expression to a `@NonNull` parameter is unsafe, causing the warning. Annotating `createTestClass`'s parameter as `@Nullable` tells NullAway that this method is allowed to receive `null`, which resolves the reported warning.
