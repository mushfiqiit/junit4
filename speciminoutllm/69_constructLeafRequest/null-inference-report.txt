

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `ErrorReportingRunner.ErrorReportingRunner` parameter `Class<?> testClass` | `@Nullable` | The call at the warning site, `new ErrorReportingRunner(null, e)`, intentionally passes `null` for the test class, so this parameter must be nullable. |
| `ErrorReportingRunner.ErrorReportingRunner` parameter `Throwable cause` | no annotation, i.e. default `@Nonnull` | The call passes the caught exception `e`, which is non-null, and the reported warning is not about this argument. |

## B) Cause of the warning

The warning is caused by the call `new ErrorReportingRunner(null, e)` in `MaxCore.constructLeafRequest`. NullAway treats an unannotated constructor parameter as `@Nonnull` by default, but the first argument is the literal `null`, which is `@Nullable`. Annotating the `testClass` parameter of `ErrorReportingRunner` as `@Nullable` makes this `null` argument type-correct and resolves the reported warning.
