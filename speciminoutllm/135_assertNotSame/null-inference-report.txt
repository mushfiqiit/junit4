

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.Assert.assertNotSame(String message, Object unexpected, Object actual)` — parameter `message` | `@Nullable` | The no-message overload deliberately passes `null` for `message`, so `message` must be allowed to be null. |

B) Cause of the warning

The warning is triggered by the call `assertNotSame(null, unexpected, actual)` in the two-argument overload. NullAway treats the first parameter of the three-argument method, `String message`, as `@NonNull` by default because it is unannotated. Since the call passes the `null` literal directly into that parameter, NullAway reports an unsafe nullable-to-nonnull assignment. Annotating `message` as `@Nullable` tells NullAway that this parameter may accept `null`, which resolves the warning.

C) Corrected annotated code

```java
// === org/junit/Assert.java ===
package org.junit;

import javax.annotation.Nullable;

public class Assert {

  public static void assertNotSame(@Nullable String message, Object unexpected, Object actual) {
    throw new java.lang.Error();
  }

  public static void assertNotSame(Object unexpected, Object actual) {
    assertNotSame(null, unexpected, actual);
  }
}
```
