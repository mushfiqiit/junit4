

## A) Annotation decisions

| location | inferred annotation | reason |
|---|---|---|
| `Failure#getMessage()` return type | `@Nullable` | This method returns `Throwable#getMessage()`, which is `@Nullable` in the JDK, so `Failure#getMessage()` can also return `null`. |
| `Failure#getException()` return type | no annotation needed (`@Nonnull` by default) | It is used as the receiver for `getMessage()` and no null-dereference warning is being fixed here, so it can remain unannotated. |

## B) Cause of the warning

The warning points to the `return` statement in `Failure#getMessage()`:

```java
return getException().getMessage();
```

`Throwable#getMessage()` is treated by NullAway as returning a `@Nullable` `String`. However, `Failure#getMessage()` is unannotated, so NullAway treats its return type as `@NonNull`. Returning a `@Nullable` value from a `@NonNull` method is unsafe. Annotating `Failure#getMessage()` as `@Nullable` makes the method’s contract match the actual nullable result.

## C) Corrected annotated code

```java
// === org/junit/runner/notification/Failure.java ===
package org.junit.runner.notification;

import java.io.Serializable;
import javax.annotation.Nullable;

public class Failure implements Serializable {

  public Throwable getException() {
    throw new java.lang.Error();
  }

  @Nullable
  public String getMessage() {
    return getException().getMessage();
  }
}
```
