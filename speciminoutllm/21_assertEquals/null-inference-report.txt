

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `String message` parameter of `assertEquals(String message, byte expected, byte actual)` | `@Nullable` | JUnit’s no-message overload intentionally calls the three-argument overload with `null` to represent “no message”, so this parameter must be treated as nullable. |

B) Cause of the warning

The warning is caused by the `null` literal passed on line 11 in the call `assertEquals(null, expected, actual);`. Since the `String message` parameter of the three-argument overload has no nullness annotation, NullAway treats it as `@NonNull` by default. Passing `null` to a `@NonNull` parameter is therefore reported as unsafe. Marking `message` as `@Nullable` tells NullAway that a `null` message is explicitly allowed, which resolves the warning.
