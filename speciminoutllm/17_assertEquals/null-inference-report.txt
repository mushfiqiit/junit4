

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `Assert.assertEquals(String message, double expected, double actual, double delta)` — `message` parameter | `@Nullable` | The 3-argument overload intentionally passes `null` when no assertion message is supplied, so the message parameter must be nullable. |
| All other parameters/return types involved | none | The other parameters are primitive `double` values and the method returns `void`, so they are not relevant to this nullability warning. |

B) Cause of the warning

The warning is caused by the `null` literal passed as the first argument in:

```java
assertEquals(null, expected, actual, delta);
```

NullAway treats an unannotated `String` parameter as `@NonNull` by default, while a `null` literal is `@Nullable`. Therefore, passing `null` to the `message` parameter is flagged as unsafe. Annotating `message` as `@Nullable` makes the parameter’s intended contract explicit and resolves the warning.

C) Corrected annotated code

```java
// === junit/framework/Assert.java ===
package junit.framework;

import javax.annotation.Nullable;

@Deprecated
public class Assert {

  public static void assertEquals(@Nullable String message, double expected, double actual, double delta) {
    throw new java.lang.Error();
  }

  public static void assertEquals(double expected, double actual, double delta) {
    assertEquals(null, expected, actual, delta);
  }
}
```
