

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.runners.model.FrameworkMethod#invokeExplosively` formal varargs parameter `params` | `@Nullable` | The caller explicitly passes `null` as the varargs array when `paramCount == 0`, so the array reference itself must be allowed to be null. |
| `org.junit.runners.parameterized.BlockJUnit4ClassRunnerWithParameters#parameters` field | `@Nonnull` by default / no annotation needed | It is only used in the branch where parameters are expected to be present, and it does not need to be annotated to resolve the reported warning. |

B) Cause of the warning

The warning is caused by the call:

```java
method.invokeExplosively(null, paramCount == 0 ? (Object[]) null : parameters);
```

The second actual argument is a ternary expression that can be null because the first branch is `(Object[]) null`. The target method `FrameworkMethod.invokeExplosively` has an unannotated `Object... params` parameter, so NullAway treats the varargs array reference as `@NonNull`. Therefore, passing a potentially null array is reported as unsafe. Annotating the formal `params` parameter as `@Nullable` tells NullAway that the varargs array reference may be null, which fixes this warning.
