

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `Assert#assertSame(String message, Object expected, Object actual)` parameter `message` | `@Nullable` | The no-message overload calls `assertSame(null, expected, actual)`, so the `message` parameter must be allowed to be null. |

No other annotations are needed for this warning; the remaining parameters are left unannotated and therefore remain `@Nonnull` by default.

## B) Cause of the warning

The warning occurs on the call:

```java
assertSame(null, expected, actual);
```

NullAway sees the literal `null` being passed to the `message` parameter of:

```java
public static void assertSame(String message, Object expected, Object actual)
```

Because `message` is unannotated, NullAway treats it as `@Nonnull`. A `null` literal is `@Nullable`, so passing it where `@Nonnull` is required is reported as unsafe.

Annotating `message` as `@Nullable` tells NullAway that this parameter may legitimately receive `null`, which matches the behavior of the two-argument `assertSame` overload.

## C) Corrected annotated code

```java
// === org/junit/Assert.java ===
package org.junit;

import javax.annotation.Nullable;

public class Assert {

  public static void assertSame(@Nullable String message, Object expected, Object actual) {
    throw new java.lang.Error();
  }

  public static void assertSame(Object expected, Object actual) {
    assertSame(null, expected, actual);
  }
}
```
