

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| Anonymous `Callable<Object>` `call()` return type in `MethodRoadie.runWithTimeout` | `@Nullable` | This method explicitly returns `null`, and its result is only used through `Future.get(...)` where the value is ignored, so a nullable return is accurate. |

No other parameters, return types, or fields involved in this warning need annotations.

## B) Cause of the warning

The warning is triggered by the `return null;` statement inside the anonymous `Callable<Object>.call()` method. Because the unannotated return type `Object` is treated by NullAway as `@NonNull`, returning the `null` literal is considered unsafe. Annotating the `call()` return type as `@Nullable` tells NullAway that this return value may legitimately be null, which resolves the diagnostic without changing any logic.
