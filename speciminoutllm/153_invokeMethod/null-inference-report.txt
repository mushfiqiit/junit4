

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `FrameworkMethod.invokeExplosively(final Object target, final @Nullable Object... params)` — `params` | `@Nullable` | `RunAfterParams.invokeMethod` intentionally passes a `null` varargs array when the invoked method has no parameters, so `invokeExplosively` must accept a nullable varargs array. |
| `BlockJUnit4ClassRunnerWithParameters.parameters` | `@Nonnull` / left unannotated | This field is used as the non-null parameter array in the non-null branch of the ternary and does not need to be nullable to fix the reported warning. |

B) Cause of the warning

The warning occurs at the call to `method.invokeExplosively(...)`, where the second argument is the ternary expression `paramCount == 0 ? (Object[]) null : parameters`. Because the ternary has a `null` branch, NullAway infers the argument as `@Nullable`. In the unannotated code, the `Object... params` parameter of `FrameworkMethod.invokeExplosively` is treated as a `@NonNull` varargs array, so passing the potentially null expression is flagged. Annotating `params` as `@Nullable` tells NullAway that `invokeExplosively` accepts a `null` varargs array, resolving the reported warning. The separate `null` passed for `target` is not the reported warning and is left unchanged.
