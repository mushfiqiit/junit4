

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.Assert.assertArrayEquals(String message, float[] expecteds, float[] actuals, float delta)` — `message` parameter | `@Nullable` | This parameter is passed the literal `null` by the overload that has no message, so it must be declared nullable. |
| Other parameters in the same method | no annotation / default non-null | They are not involved in this warning and should remain non-null by default. |

## B) Cause of the warning

The warning is reported on the call `assertArrayEquals(null, expecteds, actuals, delta);`, where the first argument is the literal `null`. Since the `message` parameter of `assertArrayEquals(String message, ...)` is unannotated, NullAway treats it as `@NonNull`, so passing a nullable `null` value to it is flagged. Annotating `message` as `@Nullable` tells NullAway that this parameter may legally receive `null`, which resolves the warning.
