

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.runners.model.FrameworkMethod.invokeExplosively` second parameter `params` | `@Nullable` | The caller explicitly passes `(Object[]) null` when the method has zero parameters, so the varargs array argument can be null. |
| `org.junit.runners.parameterized.BlockJUnit4ClassRunnerWithParameters.parameters` field | `@Nonnull` (left unannotated) | The field is assigned from `toArray(...)` and dereferenced elsewhere, so the array reference itself is non-null; the nullable expression comes from the ternary’s explicit null branch. |
| `org.junit.runners.model.FrameworkMethod.invokeExplosively` first parameter `target` (kept) | `@Nullable` | The same call and other original callers pass `null` as the target, so the target object is allowed to be null. |

## B) Cause of the warning

The warning is triggered by the second argument to `method.invokeExplosively(...)` on the reported line:

```java
paramCount == 0 ? (Object[]) null : parameters
```

This expression has type `Object[]` and can be null because one branch is an explicit `(Object[]) null`. If the corresponding varargs parameter of `FrameworkMethod.invokeExplosively` is treated as non-null, NullAway reports that a @Nullable expression is being passed where @NonNull is required. Annotating the `params` parameter as `@Nullable` makes the method accept the null varargs array used for zero-parameter methods, resolving this warning. The `parameters` field itself should remain non-null/unannotated.
