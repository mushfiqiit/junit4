

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `Assert.assertEquals` parameter `message` | `@Nullable` unchanged | The message may legitimately be null and is already declared nullable at the public API entry point. |
| `Assert.failNotEquals` parameter `message` | `@Nullable` | This private helper receives the nullable message from `assertEquals`, so its `message` parameter must also be nullable. |
| `Assert.failNotEquals` parameters `expected`, `actual` | unannotated / `@Nonnull` default | These receive non-null boxed doubles in the relevant call and are not involved in the reported warning. |

B) Cause of the warning

The warning occurs at the call `failNotEquals(message, Double.valueOf(expected), Double.valueOf(actual))` inside `assertEquals`. The local argument `message` is declared `@Nullable`, but the callee `failNotEquals` declares its `message` parameter as an unannotated `String`, which NullAway treats as `@NonNull` by default. NullAway therefore reports that a nullable value is being passed where a non-null value is required. Annotating `failNotEquals`’s `message` parameter as `@Nullable` makes the callee accept a nullable message and resolves the warning.
