

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `Assert.assertEquals(String message, double expected, double actual)` parameter `message` | `@Nullable` | The deprecated no-message overload deliberately passes a literal `null` as the message, so `message` must be allowed to be null. |

B) Cause of the warning

The warning is caused by the call `assertEquals(null, expected, actual)` on line 7. NullAway resolves this call to the overload `assertEquals(String message, double expected, double actual)`, and because the `message` parameter is unannotated, NullAway treats it as `@NonNull`. The literal `null` is therefore an invalid argument for that `@NonNull` parameter. Annotating `message` as `@Nullable` tells NullAway that null is explicitly allowed in this position, resolving the warning without changing any logic.

C) Corrected annotated code

```java
// === org/junit/Assert.java ===
package org.junit;

import javax.annotation.Nullable;

public class Assert {

  @Deprecated
  public static void assertEquals(double expected, double actual) {
    assertEquals(null, expected, actual);
  }

  @Deprecated
  public static void assertEquals(@Nullable String message, double expected, double actual) {
    throw new java.lang.Error();
  }
}
```
