

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.Assert#assertSame(String message, Object expected, Object actual)` parameter `message` | `@Nullable` | The existing reduced code already treats the assertion message as optional, and the caller is allowed to pass `null` for the message. |
| `org.junit.Assert#failNotSame(String message, Object expected, Object actual)` parameter `message` | `@Nullable` | The original JUnit implementation explicitly checks `message != null`, proving that `message` is intended to be allowed as `null`. |
| Other parameters (`expected`, `actual`) | no annotation / `@Nonnull` by default | They are unrelated to this specific NullAway warning, so they should not be changed. |

## B) Cause of the warning

The warning occurs at the call to `failNotSame(message, expected, actual)` inside `assertSame`. The parameter `message` in `assertSame` is annotated `@Nullable`, so NullAway treats it as possibly `null`. However, the parameter `message` in `failNotSame` is unannotated, which NullAway treats as `@Nonnull` by default. Therefore, passing a `@Nullable` value into a `@Nonnull` parameter is unsafe and produces the warning.

Annotating the `message` parameter of `failNotSame` as `@Nullable` fixes the warning because it tells NullAway that `failNotSame` is allowed to receive a `null` message, matching the original JUnit logic that guards `message` with `if (message != null)`.

package org.junit;

import javax.annotation.Nullable;

public class Assert {

  public static void assertSame(@Nullable String message, Object expected, Object actual) {
    if (expected == actual) {
      return;
    }
    failNotSame(message, expected, actual);
  }

  private static void failNotSame(@Nullable String message, Object expected, Object actual) {

  }
