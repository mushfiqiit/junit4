

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `message` parameter of `Assert.assertEquals(String message, Object expected, Object actual)` | `@Nullable` | The no-message `assertEquals(Object, Object)` overload intentionally passes `null` as the message, so the message parameter may be null. |

B) Cause of the warning

The warning is caused by the call `assertEquals(null, expected, actual);` on line 10, where the `null` literal is passed to the `message` parameter of the three-argument `assertEquals` method. Because `message` is unannotated, NullAway treats it as `@NonNull` by default, and passing a `null` literal is unsafe. Marking `message` as `@Nullable` tells NullAway that `null` is an allowed value for that parameter, which resolves the warning.

import javax.annotation.Nullable;
