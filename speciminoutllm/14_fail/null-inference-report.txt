

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `Assert.fail(String message)` parameter `message` | `@Nullable` | The no-arg `fail()` method intentionally calls `fail(null)`, so the message parameter may be null. |

## B) Cause of the warning

The warning is triggered on the `fail(null)` call inside `fail()`. Since `fail(String message)` has no nullness annotation on `message`, NullAway treats that parameter as `@NonNull` by default, while the literal `null` is `@Nullable`. Annotating `message` as `@Nullable` tells NullAway that null is allowed there, resolving the warning.

## C) Corrected annotated code

```java
// === junit/framework/Assert.java ===
package junit.framework;

import javax.annotation.Nullable;

@Deprecated
public class Assert {

  public static void fail(@Nullable String message) {
    throw new java.lang.Error();
  }

  public static void fail() {
    fail(null);
  }
}
```
