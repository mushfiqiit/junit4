

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.Assert.failEquals(String message, Object actual)` parameter `message` | `@Nullable` | The original `failEquals` body checks `message != null`, and callers may pass a null user-supplied message from `assertNotEquals`. |
| `org.junit.Assert.assertNotEquals(...)` parameter `message` | `@Nullable` (already present) | The public assertion method already declares its optional failure message as nullable. |
| `org.junit.Assert.failEquals(String message, Object actual)` parameter `actual` | leave unannotated, i.e. `@NonNull` by default | The warning is only about `message`, and the reduced call passes `Float.valueOf(actual)`, which is treated as non-null. |

B) Cause of the warning

The warning points to the call `failEquals(message, Float.valueOf(actual));` inside `assertNotEquals`. There, `message` is a `@Nullable` parameter of `assertNotEquals`, but the `message` parameter of `failEquals` is unannotated and therefore treated by NullAway as `@NonNull`. Marking `failEquals`’s `message` parameter `@Nullable` matches the actual nullability contract and resolves the warning.
