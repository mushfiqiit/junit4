

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.runners.model.Annotatable#getAnnotation` return type | `@Nullable` | The annotation lookup may legitimately return `null` when the requested annotation is not present. |
| `org.junit.runners.model.TestClass#getAnnotation` return type | `@Nullable` | The implementation returns `null` and may return the nullable result of `Class.getAnnotation`, so the override must also declare a nullable return type. |

No parameter or field annotations are required to fix this specific warning, so they are left unannotated.

## B) Cause of the warning

The warning points to line 11 of `TestClass.java`, which is the statement `return null;`. NullAway treats the unannotated return type `T` as `@NonNull`, but a `null` literal is `@Nullable`, so returning it from a method with a `@NonNull` return type is unsafe. Marking the return type of both the overridden interface method `Annotatable#getAnnotation` and the implementation `TestClass#getAnnotation` as `@Nullable` makes the null return, and the nullable result of `clazz.getAnnotation(annotationType)`, compatible with the declared method return type.

// === org/junit/runners/model/Annotatable.java ===
package org.junit.runners.model;

import java.lang.annotation.Annotation;
import javax.annotation.Nullable;

public interface Annotatable {

  <T extends Annotation> @Nullable T getAnnotation(Class<T> annotationType);
}


// === org/junit/runners/model/TestClass.java ===
package org.junit.runners.model;

import java.lang.annotation.Annotation;
import javax.annotation.Nullable;

public class TestClass implements Annotatable {

  private final Class<?> clazz;

  public <T extends Annotation> @Nullable T getAnnotation(Class<T> annotationType) {
    if (clazz == null) {
      return null;
    }
    return clazz.getAnnotation(annotationType);
  }
}
