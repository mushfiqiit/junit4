

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `Suite#Suite(Class<?>, Class<?>[])` parameter `klass` | `@Nullable` | `emptySuite()` deliberately constructs a suite using a null `Class<?>`. |
| `Suite#Suite(RunnerBuilder, Class<?>, Class<?>[])` parameter `klass` | `@Nullable` | It receives the same nullable `klass` from the two-argument `Suite` constructor. |
| `Suite#Suite(Class<?>, List<Runner>)` parameter `klass` | `@Nullable` | It receives the nullable `klass` from the `RunnerBuilder` constructor and forwards it to `super`. |
| `ParentRunner#ParentRunner(Class<?>)` parameter `testClass` | `@Nullable` | The nullable suite class is passed here for the empty-suite case. |
| `RunnerBuilder#runners(Class<?>, Class<?>[])` parameter `parent` | `@Nullable` | `Suite` can call `runners` with a null parent class when constructing an empty suite. |

All other parameters/return types in this path are guaranteed non-null in this scenario and can remain unannotated, since NullAway treats unannotated references as `@NonNull`.

## B) Cause of the warning

The warning is triggered at `Suite.java:13`, where `new Suite((Class<?>) null, new Class<?>[0])` passes a `null` literal to the first parameter of `Suite(Class<?>, Class<?>[])`. NullAway assumes that unannotated reference-type parameters are `@NonNull`, while a `null` literal is `@Nullable`, so it reports an unsafe null pass. Marking the `klass` parameter as `@Nullable`—and also marking the directly forwarded `testClass` / `parent` parameters that can receive the same null in this call chain as `@Nullable`—tells NullAway that null is a valid value at those locations, resolving the warning.
