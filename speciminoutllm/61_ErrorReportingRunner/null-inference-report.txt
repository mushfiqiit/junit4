

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `ErrorReportingRunner(@Nullable Class<?> testClass, Throwable cause)` parameter `testClass` | `@Nullable` (kept) | Existing call sites such as `new ErrorReportingRunner(null, e)` show that this class argument can really be null. |
| `ErrorReportingRunner(Throwable cause, Class<?>... testClasses)` varargs parameter `testClasses`, element type | `@Nullable` | This constructor receives the nullable `testClass` from the other constructor, so its varargs element type must be allowed to be null. |

No other fields, return types, or parameters need annotations to fix this specific warning; under NullAway, unannotated types remain `@NonNull` by default.

## B) Cause of the warning

The warning points to the constructor delegation:

```java
this(cause, testClass);
```

Here, `testClass` is declared as `@Nullable Class<?>`. The called constructor has a varargs parameter:

```java
Class<?>... testClasses
```

Because the varargs element type is unannotated, NullAway treats each element as `@NonNull`. Passing the potentially null `testClass` as one of the varargs elements is therefore reported as unsafe. Annotating the varargs element type as `@Nullable Class<?>... testClasses` tells NullAway that null class values are accepted in that array, which resolves the warning.
