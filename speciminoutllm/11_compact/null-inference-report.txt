

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `junit.framework.Assert.format` parameter `message` | `@Nullable` | The original `format` method explicitly checks `message != null` before using it, and `ComparisonCompactor.compact` forwards its already-`@Nullable` `message` parameter to it. |
| `ComparisonCompactor.compact` parameter `message` | `@Nullable` existing | This parameter is the nullable expression being passed into `Assert.format`, so it correctly remains `@Nullable`. |
| `junit.framework.Assert.format` return type | unannotated/default `@Nonnull` | `format` is expected to return a non-null formatted `String`, so no return-type annotation is needed to fix this warning. |

## B) Cause of the warning

The warning is on the first `Assert.format(...)` call in `ComparisonCompactor.compact`, where the `@Nullable` parameter `message` is passed as the first argument. Because `Assert.format` has no nullness annotations, NullAway treats its first parameter `message` as `@Nonnull` by default, so passing a possibly-null value is reported as unsafe. The original JUnit `Assert.format` body shows that `message` is null-checked before dereferencing, so the correct fix is to annotate that parameter as `@Nullable`; this allows `ComparisonCompactor.compact` to forward its nullable message safely without changing logic.
