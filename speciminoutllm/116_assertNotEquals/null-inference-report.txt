

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `Assert.assertNotEquals(String message, long unexpected, long actual)` parameter `message` | `@Nullable` | The no-message overload intentionally passes `null` for this argument, so the `String message` parameter must be allowed to accept null. |
| Other parameters / return type / fields in the warning path | no annotation | These are primitive `long` parameters or `void` return types and are not null-related locations needing an annotation for this warning. |

B) Cause of the warning

The warning points to the call `assertNotEquals(null, unexpected, actual)` inside the two-argument `assertNotEquals` overload. Without an annotation, NullAway treats the `String message` parameter of the three-argument overload as `@NonNull`, so passing the literal `null` is rejected. Marking `message` as `@Nullable` tells NullAway that this parameter is intended to accept null, which resolves the warning.

C) Corrected annotated code

```java
// === org/junit/Assert.java ===
package org.junit;

import javax.annotation.Nullable;

public class Assert {

  public static void assertNotEquals(@Nullable String message, long unexpected, long actual) {
    throw new java.lang.Error();
  }

  public static void assertNotEquals(long unexpected, long actual) {
    assertNotEquals(null, unexpected, actual);
  }
}
```
