

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.Assert#assertEquals` parameter `message` | `@Nullable` | This parameter is already correctly nullable, since the method explicitly handles `message == null`. |
| `org.junit.Assert#failNotEquals` parameter `message` | `@Nullable` | This private helper receives the same possibly-null `message` from `assertEquals`, and the original JUnit behavior treats `message` as optional. |

No `@Nonnull` annotation is required for this fix.

## B) Cause of the warning

The warning occurs on the call `failNotEquals(message, expected, actual)` inside `assertEquals`. The `message` argument is annotated `@Nullable`, but the `message` parameter of `failNotEquals` is unannotated, so NullAway treats it as `@NonNull`. Therefore, NullAway flags the call as potentially passing a null value to a non-null parameter. Annotating `failNotEquals`'s `message` parameter as `@Nullable` declares that the helper accepts a null message, which matches the actual JUnit usage and resolves the warning.

import javax.annotation.Nullable;

public class Assert {

  public static void assertEquals(@Nullable String message, Object expected, Object actual) {
    if (equalsRegardingNull(expected, actual)) {
      return;
    }
    if (expected instanceof String && actual instanceof String) {
      String cleanMessage = message == null ? "" : message;
      throw new ComparisonFailure(cleanMessage, (String) expected, (String) actual);
    } else {
      failNotEquals(message, expected, actual);
    }
  }

  private static boolean equalsRegardingNull(Object expected, Object actual) {
    throw new java.lang.Error();
  }

  private static void failNotEquals(@Nullable String message, Object expected, Object actual) {
    throw new java.lang.Error();
  }
}
