

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `junit.framework.Assert.assertEquals(String, int, int)` first parameter `message` | `@Nullable` | The two-argument `assertEquals` overload intentionally passes `null` when no message is supplied, so the message parameter must be declared nullable. |

B) Cause of the warning

The warning occurs at the call `assertEquals(null, expected, actual)`, where the literal `null` is passed as the `String message` argument to `assertEquals(String, int, int)`. Because that parameter is unannotated, NullAway treats it as `@NonNull` and therefore rejects the `null` literal. Annotating the `message` parameter with `@Nullable` tells NullAway that this parameter is allowed to be `null`, which resolves the warning without changing any logic.

C) Corrected annotated code

```java
// === junit/framework/Assert.java ===
package junit.framework;

import javax.annotation.Nullable;

@Deprecated
public class Assert {

  public static void assertEquals(@Nullable String message, int expected, int actual) {
    throw new java.lang.Error();
  }

  public static void assertEquals(int expected, int actual) {
    assertEquals(null, expected, actual);
  }
}
```
