

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.Assert.fail(String message)` parameter `message` | `@Nullable` | The no-arg `fail()` overload passes `null` to this parameter, so the message parameter must be allowed to be null. |

## B) Cause of the warning

The warning is caused by the call `fail(null)` inside the no-arg `fail()` method. By default, NullAway treats the `String message` parameter of `fail(String message)` as `@NonNull`, so passing the literal `null` is considered unsafe. Annotating `message` with `@Nullable` fixes the warning because it tells NullAway that `null` is an acceptable value for that parameter.

## C) Corrected annotated code

```java
// === org/junit/Assert.java ===
package org.junit;

import javax.annotation.Nullable;

public class Assert {

  public static void fail(@Nullable String message) {
    throw new java.lang.Error();
  }

  public static void fail() {
    fail(null);
  }
}
```
