

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.Assert.assertNotEquals` parameter `message` | `@Nullable` (already present) | JUnit assertion messages are optional, and the downstream helper checks `message != null` before using it. |
| `org.junit.Assert.failEquals` parameter `message` | `@Nullable` | This helper receives the same optional message from `assertNotEquals` and is designed to tolerate a null value. |

## B) Cause of the warning

The warning is reported at the `failEquals(message, actual);` call inside `assertNotEquals`. The `message` parameter of `assertNotEquals` is annotated `@Nullable`, so `message` may be null. However, the `message` parameter of `failEquals` is unannotated, so NullAway treats it as `@Nonnull` by default. Therefore, passing the `@Nullable` value into `failEquals` is unsafe under NullAway’s default model. Annotating `failEquals`’s `message` parameter as `@Nullable` tells NullAway that this helper accepts a null message, which matches the original JUnit implementation’s null check.
