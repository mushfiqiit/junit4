

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `junit.framework.Assert.assertNotSame` parameter `message` | `@Nullable` | Keep the existing annotation because this value may be null and is forwarded to `failSame`, which explicitly handles null. |
| `junit.framework.Assert.failSame` parameter `message` | `@Nullable` | The original `failSame` implementation checks `message != null`, so null is a legal value for this parameter. |

B) Cause of the warning

The warning points to the call `failSame(message);` inside `assertNotSame`. The parameter `message` in `assertNotSame` is annotated `@Nullable`, so NullAway treats it as possibly null. The parameter of `failSame` is unannotated, so under NullAway’s defaults it is treated as `@NonNull`. Passing a `@Nullable` expression to that `@NonNull` parameter is therefore flagged. Annotating the `message` parameter of `failSame` as `@Nullable` makes the method contract match its actual behavior, because it already accepts null.
