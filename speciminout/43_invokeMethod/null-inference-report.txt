

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.runners.model.FrameworkMethod#invokeExplosively(Object, Object...)` parameter `params` | `@Nullable` | The call intentionally passes `(Object[]) null` when `paramCount == 0`, so the varargs array may be null. |
| `org.junit.runners.parameterized.BlockJUnit4ClassRunnerWithParameters#parameters` field | `@Nonnull` / left unannotated | The field is assigned from a non-null `toArray(...)` result and its length/elements are dereferenced elsewhere, so the field itself is non-null; the nullable value comes from the explicit `null` branch in the call. |

B) Cause of the warning

The warning points to the argument:

```java
paramCount == 0 ? (Object[]) null : parameters
```

NullAway infers this expression as `@Nullable` because one branch of the ternary is the `null` literal. The called parameter `params` in `FrameworkMethod.invokeExplosively` is an array under the hood, and if it is treated as a `@NonNull` array, passing a possibly-null `Object[]` is unsafe. The fix is to annotate the varargs/array parameter `params` as `@Nullable`, since callers may pass a null array for zero parameters. The `parameters` field itself remains non-null.
