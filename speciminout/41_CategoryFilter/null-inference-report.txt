

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `CategoryFilter` constructor parameter `inclusions` | `@Nullable` (keep existing) | The warning’s argument is already nullable and the original code can pass `null` when the corresponding category annotation is absent. |
| `Categories.createSet` parameter `classes` | `@Nullable` | The original `createSet` explicitly checks `classes == null` and is called with `null` in the original JUnit code, so it must accept a nullable array. |

B) Cause of the warning

The warning is on the call `included = createSet(inclusions)`. `inclusions` is declared `@Nullable Class<?>[]`, but `createSet`’s parameter `classes` has no annotation and is therefore treated as `@NonNull` by NullAway. Passing a nullable array to a nonnull parameter is unsafe according to NullAway. Since the original JUnit implementation null-checks this parameter and may receive `null`, the correct fix is to annotate `createSet`’s parameter as `@Nullable`.

    private final Set<Class<?>> excluded;

    private final boolean includedAny;

    private final boolean excludedAny;

    private CategoryFilter(
        boolean matchAnyIncludes,
        @Nullable Class<?>[] inclusions,
        boolean matchAnyExcludes,
        @Nullable Class<?>[] exclusions) {
      includedAny = matchAnyIncludes;
      excludedAny = matchAnyExcludes;
      included = createSet(inclusions);
      excluded = createSet(exclusions);
    }
  }

  private static Set<Class<?>> createSet(@Nullable Class<?>[] classes) {
    throw new java.lang.Error();
  }
}
