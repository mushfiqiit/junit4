

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `TemporaryFolder.parentFolder` field | `@Nullable` unchanged | The original class explicitly declares this field as `@Nullable`, and it may be absent when no parent folder is configured. |
| `TemporaryFolder.createTemporaryFolderIn(File parentFolder)` parameter | `@Nullable` add | The caller passes the nullable `parentFolder` field, and the original implementation handles a null directory before using it. |
| `TemporaryFolder.createTemporaryFolderIn(...)` return type | left unannotated, i.e. `@Nonnull` by NullAway default | The method returns a created folder or throws, so its return value is non-null, and no return-type annotation is needed to fix this warning. |

## B) Cause of the warning

The warning points to the call:

```java
folder = createTemporaryFolderIn(parentFolder);
```

NullAway knows that the `parentFolder` field is `@Nullable` because it is annotated that way. The parameter of `createTemporaryFolderIn` is unannotated, so NullAway treats it as `@NonNull` by default. Therefore, passing the nullable field value to the unannotated parameter is reported as unsafe.

Marking the `createTemporaryFolderIn` parameter `@Nullable` tells NullAway that the method accepts a nullable `File`, matching the original JUnit implementation, which explicitly handles a null parent folder.
