

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `Computer.getSuite(...)` return type | `@Nonnull` by default, left unannotated | Callers in the original program use the returned `Runner` as non-null, and this return is not the nullable expression causing the warning. |
| `Computer.getRunner(...)` return type | `@Nullable`, already present and unchanged | It represents a value that may be null because it ultimately wraps `RunnerBuilder.runnerForClass`, which is annotated `@Nullable`. |
| Anonymous `RunnerBuilder.runnerForClass(...)` inside `Computer.getSuite`, return type | `@Nullable`, add this annotation | This override returns the `@Nullable` result of `getRunner(...)` and overrides the `@Nullable` `RunnerBuilder.runnerForClass` method, so its return type must also be `@Nullable`. |

B) Cause of the warning

The warning is on the `return getRunner(builder, testClass);` statement inside the anonymous `RunnerBuilder` created in `Computer.getSuite`. That anonymous `runnerForClass` method has an unannotated `Runner` return type, which NullAway treats as `@Nonnull`, but the expression being returned is `getRunner(...)`, whose return type is annotated `@Nullable`. Therefore NullAway reports that a possibly-null expression is being returned from a method with a non-null return type. Adding `@Nullable` to the anonymous method’s return type makes its nullability contract match both the nullable value being returned and the overridden `@Nullable RunnerBuilder.runnerForClass` method.
