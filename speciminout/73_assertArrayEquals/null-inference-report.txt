

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.Assert#assertArrayEquals(String, int[], int[])` parameter `message` | `@Nullable` | This is the public assertion-message parameter and is already correctly marked nullable because the message may be omitted. |
| `org.junit.Assert#internalArrayEquals(String, Object, Object)` parameter `message` | `@Nullable` | This private helper is called with the public method’s nullable `message`, so it must also accept `null` to avoid the NullAway error. |

No other annotations are required for this warning.

## B) Cause of the warning

The warning occurs at the call:

```java
internalArrayEquals(message, expecteds, actuals);
```

Inside `assertArrayEquals`, the local parameter `message` is annotated `@Nullable`, so NullAway knows it may be `null`. However, the private helper `internalArrayEquals` declares its first parameter as:

```java
String message
```

With no annotation, NullAway treats it as `@Nonnull` by default. Therefore, passing the nullable `message` to it is unsafe.

Adding `@Nullable` to the `message` parameter of `internalArrayEquals` tells NullAway that this helper intentionally accepts a null message, which matches how the original JUnit assertion-message API behaves and resolves the warning.
