

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.internal.runners.JUnit4ClassRunner#testAborted(RunNotifier, Description, Throwable)` parameter `e` | `@Nonnull` | The `Throwable` is the actual exception being reported as a test failure, and JUnit’s `Failure` constructor is intended to receive a non-null exception, so `e` is guaranteed non-null here. |
| `org.junit.runner.notification.Failure#Failure(Description, Throwable)` parameter `thrownException` | unannotated / non-null | It is the exception stored in a `Failure` object and should not be nullable; no usage evidence suggests `Failure` accepts a null exception. |

## B) Cause of the warning

The warning is on the call:

```java
notifier.fireTestFailure(new Failure(description, e));
```

specifically the argument `e` passed to the second parameter of the `Failure` constructor. In the reduced code, `e` is declared `@Nullable Throwable`, while the `Failure` constructor parameter `thrownException` is unannotated and therefore treated as `@NonNull` by NullAway. NullAway therefore flags the potential passing of a null `Throwable` into a non-null constructor parameter.

Fixing this by annotating `e` as `@Nonnull` reflects the fact that this parameter is used to wrap a real exception in a `Failure`; it is not a value that can legitimately be null at this call site. The `Failure` object itself is a fresh object reference and is non-null, so `RunNotifier.fireTestFailure(Failure)` does not need to accept a nullable `Failure` for this warning.
