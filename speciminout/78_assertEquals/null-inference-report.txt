

A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---|---|
| `org.junit.Assert.assertEquals(@Nullable String message, ...)` parameter `message` | `@Nullable` | This public JUnit assertion method accepts an optional message, so `null` is a valid input. |
| `org.junit.Assert.failNotEquals(String message, Object expected, Object actual)` parameter `message` | `@Nullable` | This private helper is called with the nullable `message` from `assertEquals` and must therefore accept a null message. |

B) Cause of the warning

The warning occurs at the call `failNotEquals(message, Float.valueOf(expected), Float.valueOf(actual))` because `message` is declared `@Nullable` in `assertEquals`, while the first parameter of `failNotEquals` is unannotated and therefore treated by NullAway as `@NonNull`. Passing a potentially null value to that parameter is reported as unsafe. Annotating `failNotEquals`’s `message` parameter as `@Nullable` tells NullAway that the helper accepts a null message, resolving the warning.
