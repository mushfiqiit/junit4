

## A) Annotation decisions

| location | inferred annotation | one-sentence reason |
|---|---:|---|
| `org.junit.internal.requests.MemoizingRequest#createRunner()` return type | `@Nullable` | The abstract factory method can return null because implementations, such as `ClassRequest`, may return the nullable result of `safeRunnerForClass`. |
| `org.junit.internal.requests.ClassRequest#createRunner()` return type | `@Nullable` | This method directly returns `safeRunnerForClass(fTestClass)`, which is declared to return `@Nullable Runner`. |
| `org.junit.runners.model.RunnerBuilder#safeRunnerForClass()` return type | `@Nullable` (unchanged) | The existing annotation already indicates that the builder may be unable to create a runner. |
| `ClassRequest.fTestClass` and the `safeRunnerForClass` parameter | unannotated, i.e. default `@Nonnull` | There is no evidence in this warning context that these values are null, and they are not the source of the reported return-type warning. |

## B) Cause of the warning

The warning is on the `return` statement in `ClassRequest.createRunner()`:

```java
return new CustomAllDefaultPossibilitiesBuilder().safeRunnerForClass(fTestClass);
```

`RunnerBuilder.safeRunnerForClass` is annotated with `@Nullable` return type, so NullAway treats the returned `Runner` expression as possibly null. However, `createRunner()` is unannotated, so NullAway treats its return type as `@Nonnull Runner`. Returning a possibly-null expression from a method declared to return non-null is therefore unsafe. Annotating `createRunner()` as `@Nullable` — and the abstract method it overrides, so the override remains consistent — makes the declared return type nullable and resolves the warning.
